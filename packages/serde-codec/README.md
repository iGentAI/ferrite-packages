# serde-codec

A compact, non-self-describing binary serde codec using unsigned LEB128 varints
and zig-zag encoding for signed values. It embeds precompiled WebAssembly
modules inside an app's source without exhausting the source budget: the same
module graph takes ~7.6 MB as JSON and ~2 MB through this codec.

Because the format carries no type information, encoder and decoder must agree
on the types. That holds because both are compiled into the same consuming app.

## Status

Stable and intentionally finished: one file (`src/mod.rs`, 878 lines) mounted at
`codec` by applications that embed precompiled WebAssembly modules (including
SQLite-guest and `qjs-engine`-backed consumers), with no separate roadmap. Its
14 unit tests in `src/mod.rs` travel with the source and run inside every
consumer alongside the consumers' WebAssembly-loading gates.

## Ferrite Platform Shape

This is a vendored source package, not a crate and not a service. Consuming
applications are deployable Ferrite apps, and a deployable app may depend on
exactly one crate (`ferrite-app`). Because a shared crate cannot be declared
under that constraint, vendoring source through `tools/ferrite-pkg` is the only
sharing mechanism (see `packages/README.md`).

The imports follow that rule: `Serialize` and `Deserialize` come from
`ferrite_app::serde`, and everything else comes from `alloc` and `core`. There
are no external crates and `hostImports` is empty, giving this package a simple
shape: pure source from one canonical copy.

### Consuming it

```json
{ "packages": { "serde-codec": { "mount": "codec" } } }
```

A mount is a directory owned by the package, so its single file `src/mod.rs`
composes to `<app>/src/codec/mod.rs`. Declare both `extern crate alloc;` and
`pub mod codec;` in the consuming crate's root (matching `crateRoot` in
`ferrite-package.json`), then call `crate::codec::*` without extra dependencies.

### Editing

Edit `packages/serde-codec/src/mod.rs`, then sync:

```bash
node tools/ferrite-pkg/ferrite-pkg.mjs sync
```

Vendored copies carry a `@generated by ferrite-pkg` header. Never edit one in
place, since the next sync overwrites local changes.

## Not Claimed

- This package is not a service and not a second implementation of an owned
  capability. There is no codec process, endpoint, or deployment; the file
  compiles directly into the app that mounts it.
- The format is neither self-describing nor an interchange format. The wire
  carries no type information, schema, or version tag, so it cannot cross a
  trust or version boundary; encoder and decoder must be the same program
  compiled from the same types.
- Zero-byte elements are limited to 65,536 per decode. Sequence and map counts
  are not compared against remaining input bytes because `Vec<()>` and maps
  with unit keys and values encode to a count alone. Elements that consume
  input are bounded by input length; elements that consume none (`()`, unit
  structs, and structs whose fields are all skipped) share a budget of 65,536
  per `from_bytes` call across every sequence and map in the value. One more
  fails with `too many zero-byte elements`. Larger zero-byte collections encode
  but do not decode. `size_hint` caps only the initial reservation at the
  remaining input length.
- There is no I/O and no compression. The codec only transforms bytes, while
  the consumer decides where they live; the size reduction over JSON comes from
  the binary encoding itself, not a compressor.
